# DAS knowledge map

DAS turns source-faithful landing evidence into typed, source-oriented relations.
Contracts declare source identity, physical shape, target schema, keys, event-time
semantics and materialization. The generator applies generic physical projection
and history mechanics; committed generated output is reviewed, never hand-edited.

```text
landing -> contract -> generator -> source declaration
                              `--> historized/latest staging
staging -> justified handwritten preparation -> post-staging
```

Different physical shapes can produce one canonical metadata interface. A provider
name is lineage, not a parser switch. Neither a canonical timestamp's name nor a
partitioned target proves a safe acquisition cursor or efficient source scan.

Historical staging is part of the pattern even when empty. Compilation and drift
checks prove structure. Comparable aggregate checks establish whether mapped paths,
casts, arrays, keys, event time and latest winners preserve actual source data.

## Implementation lookup

Resolve **DAS authoring bindings**, **DAS code and coverage map** and **DAS commands
and credential mechanisms** through the task repository's root Project context.
They bind actual shapes, metadata order, supported/rejected capabilities, source
clocks, owned coordinates, fixtures, commands and the reference-divergence ledger.

Read mandatory **Operational restrictions** before choosing an input or preparing
an operation. Dated accepted-loss decisions and build evidence are indexed in
context, not retold here as evergreen guarantees. Source/business meaning and a
current consumer are separate from technical success.
