# DAR working boundary

Read root [AGENTS.md](../AGENTS.md), its project-context binding and the
[playbook](../ANALYTICS_PLAYBOOK.md). DAR shapes reviewed DAB meaning to answer a
question; it does not repair upstream acquisition, mapping or conceptual gaps.

- Analytical elicitation is distinct from DAB discovery. Reuse accepted answers
  and sufficient existing assets; select grain/pattern from meaning, not enums.
- Production DAR consumes DAB. Bounded traces to raw sources are verification,
  not production dependency shortcuts.
- Author supported declarations, never repairs to generated SQL. Keep an
  expressible grain constraint and verify actual compiler enforcement separately.
- Missing local layout, active input or catalog capability blocks that path,
  not independent local design. No install/reset or warehouse write by inference.
- Apply root authorization/identity rules to all connected work and mutations.

Use the root task routes for elicitation, spec authoring, structural validation,
result verification and operations. The [DAR mental map](../.agentic/knowledge/layers/dar.md)
links their reference owners. Per-claim evidence and untested scope accompany
completion; this instruction file itself declares no analytical output or deployment.
